## 启动器逻辑问题（已修复）

1. **整合包完整更新残留旧模组**：增量更新会删除旧版本管理的文件，但完整安装路径不会。overrides 变化会强制走完整安装，旧 jar 会和新 jar 并存，可能导致重复模组崩溃。现在完整安装会按增量规则删除旧版本管理、新索引不再包含的文件，用户自行添加的文件不受影响（新增 `FullInstallCleanupTests`）。
2. **启动前自动更新使用过期清单**：此前优先使用打开启动器时缓存的清单，启动器长时间运行期间发布的新 revision 不会在启动前更新。现在先获取最新签名清单，失败时再回退到缓存。
3. **游戏退出状态不区分崩溃**：正常退出、用户结束和崩溃都显示“游戏已退出”。现在非零退出码显示“游戏异常退出（代码 N）”，并根据已有输出分类给出中文提示（内存不足、Java 过低、模组不兼容、显卡驱动等）。
4. **Quilt 安装无超时和错误映射**：与 Fabric 一致，使用 45 秒超时，网络错误转为可读提示。
5. `GameLauncherVersion` 固定为 `0.1.0`：改为当前启动器版本。

## 对照 HMCL 新增的功能（2026-11-07）

| 功能 | 说明 |
| --- | --- |
| 启动前完整性检查 | 复用已安装版本前，用 CmlLib 的文件清单检查客户端、库、natives 和资源文件是否存在、大小是否一致；有问题时走正常安装流程，只补齐缺失文件并重新配置加载器。检查本身失败（如离线缺少资源索引）不阻止启动。 |
| 旧版 Forge 的 Java 上限 | 1.13 以前的 Forge（LaunchWrapper）只能用 Java 8。手动指定更高版本时，实例设置保存会被拦截，启动时也会给出明确提示；自动选择本来就会选 Java 8。 |
| 日志与崩溃报告 | 实例目录页增加“日志文件夹”“崩溃报告文件夹”。游戏异常退出后，实例卡片出现“导出崩溃报告”，打包 latest.log、最新崩溃报告、JVM 错误日志和环境摘要（版本、加载器、Java、退出码、模组列表），并隐藏登录令牌。 |
| 模组更新检查 | 模组页增加“检查更新”：按文件 SHA-1 到 Modrinth 查询同加载器、同游戏版本的最新版本，只提示比当前更新的版本；下载后校验大小和哈希，旧文件移入 .cmumcl-trash。CurseForge 独有的模组不检查。 |
| 游戏启动后 | 设置页“全局游戏设置”新增：保持启动器 / 最小化（所有游戏退出后恢复）/ 关闭启动器。有其他任务、下载或未保存修改时不会关闭，改为最小化。 |
