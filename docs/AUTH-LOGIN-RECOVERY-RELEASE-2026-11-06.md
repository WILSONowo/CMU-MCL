# 登录恢复复查、发布与实测（2026-11-06）

## 复查与修复

发布前复查发现共享登录任务的取消边界：取消某个启动任务时，它会继续等登录窗口关闭。已改为独立取消等待者，共享登录继续服务其他任务；共享登录完成后自行清理，避免全部等待者取消后留下已结束的任务影响后续启动。

恢复每次最多一次；网络/服务器暂时故障不弹重新登录窗口；拒绝、缺失或无效认证信息才进入恢复。并发启动共享窗口，取消登录不启动游戏，新会话不会被晚返回的旧启动结果覆盖。错误 JSON null 能保留正确的认证/网络错误分类。

本地通过：56 项基础/认证回归、47 项下载/更新回归，以及界面回归中的 12 项登录恢复场景。新增发布前登录恢复回归已接入 GitHub Actions，并在线通过。未发现阻止本次发布的剩余问题。

## 真实完整流程

1. 用户在已发布的 0.3.48.16 中完成初始登录，进入主界面。真实 validate 返回 204。
2. 通过同一皮肤站的 invalidate 接口主动吊销当前会话，接口返回 204，随后 validate 返回 403。这是受控的真实服务器吊销测试，没有伪造 HTTP 响应，也没有等待自然过期。
3. 在原实例（Minecraft 26.3 / Fabric 0.19.5）只点击一次“启动游戏”。客户端自动打开恢复登录窗口，原主窗口仍存在；此时没有启动 Java 游戏进程。
4. 用户手动重新登录，仅操作登录窗口，没有再次点击启动。窗口关闭后，客户端自动继续原实例启动任务。
5. 游戏进程 PID 3032 于 20:04:32（Asia/Shanghai）启动。游戏令牌与新保存的会话一致，且不同于已吊销令牌；角色一致，authlib-injector 正常加载。真实 validate 返回 204。
6. 连接 play.southmount.cn:25565，并已实际进入服务器世界。未出现会话或用户名验证失败。

完整的“会话失效 → 重新登录 → 自动继续启动 → 进服”验收通过。当前客户端及游戏保留运行。记录与进服截图位于工作区 `outputs/release-evidence/2026-11-06/auth-recovery/`；回执不包含令牌、密码或邮箱地址。临时加密认证快照仅保留在 `.tmp/auth-recovery-release/`。
